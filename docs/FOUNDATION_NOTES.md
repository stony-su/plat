   - double-jump and dash forks only from full-hold jumps;

   Design main paths from standard moves inside the §4 tables. The DJ+dash cell at dy=+9 is effectively **6** columns, not 7. Use a lint.edges annotation with a note only when the bot is demonstrably wrong.

### TOOLS — known gaps

1. §4.4 DJ+dash row at dy=+9 (table: 7 columns): the SAFE model physically reaches only 6. A level using exactly that cell fails E11 and needs a lint.edges annotation with a note (§A.3). The envelope fixtures omit that cell.
2. The bots use a reduced form of the §3 program set:
- double-jump and dash apex forks are explored only for the full-hold jump (0.05 s and 0.2 s holds get the post-apex input variants only);
- dash then double jump is tried only for non-downward dashes;
- no coyote-jump program;
- no wall-jump followed by a double jump;
- wall-jump chains mix modes only as 'zig-zag, then one final reverse hop';
- movers are modelled only at their path vertices;
- moving orbit nodes are sampled points.
All fixtures and calibration tables pass with this set, but an exotic route could be judged unreachable. Such a route needs a lint.edges annotation.
3. EXPERT gem searches assume EXPERT can reach everything SAFE reaches (they are seeded from SAFE-reached spots). An exhaustive EXPERT search runs as the fallback.
4. P1 deliverables (UI, W1–W5, endless) don't exist yet. Their lint, boot, manifest and check-all paths were verified only with fixtures and a scratch stand-in generator. Until P1 lands:
- check-all --strict fails (81 errors: missing files, types and scenes);
- full lint-levels fails with E01 'world N is missing levels'.
5. boot-test timing figures come from the Node vm, not a browser, so the CONTRACT §6 frame budgets are reported but not enforced. The canvas stub doesn't rasterize, so visuals are unverified headlessly by design.
6. glsl-lint's int/float mixing check is heuristic. It catches integer literals in float builtins and variable-operator-literal patterns, but not a function result combined with an integer literal.
7. boot-test passes empty params ({}) to scenes it doesn't know. Random UI input may navigate away (e.g. start a new game). That is accepted as long as no errors occur.

AP.Backgrounds:

AP.Midground.render(ctx, key, p):
- Screen space. Returns at once if p.quality.mid === false or bg === 'off'. Saves and restores ctx itself.
- Layout is seeded from p.L.seed, else p.seed, else hash(key). Parallax 0.32 (AP.Midground.PARALLAX).
- p.t must be L.time: the w3 particles and w4 tree growth reset when t jumps backwards (restart regrows the trees).
- w2 cluster sprites and w4 L-system prototypes are built lazily on the first frame of a level (one-time cost).

AP.TileArt:
- build(L) binds L and prebuilds up to 16 chunks around L.player, else L.cam, L.checkpoint or the 'P' in def.map. draw() also binds lazily if L changes, so build is optional.
- draw(ctx, L, cam) makes at most 2 builds per frame, nearest the view centre first, of which at most 1 may be an off-screen prefetch. A dirty chunk shows its stale canvas until rebuilt; a chunk with no canvas yet is drawn live with a lite vector pass. If no canvas can be created, every chunk draws live.
- Visible chunks re-verify a checksum of their tiles every frame, so a missed invalidate self-heals within the rebuild latency.
- invalidate(L, tx, ty) dirties only the chunk(s) within 1 tile of (tx, ty); tx/ty < 0 or NaN means check every chunk.
- dispose(L) ignores a stale L. resize() picks up AP.R.px. Extra: stats() -> {chunks, builds, live, totalBuilds, res, cap, noCanvas, broken, style}; CHAMFER = 6.
- Chunk resolution is min(px, 2) snapped so 256*res is whole pixels, plus a 2 px apron so blits never seam.
- Solid mass = SOLID + FAKE: a contour-traced outline with 6u chamfers on convex corners only (concave corners stay sharp, so art never covers walkable space), an opaque tinted body, a per-style fill, an inner glow band and a 2u pal.primary edge.
- BREAK is NOT part of the mass: individual inset, cracked blocks (lattice, crystal, stone, bark or rings per style). A BREAK block embedded in SOLID therefore shows a glowing seam, which is intentional.
- Out-of-bounds rule as in the CONTRACT; chunk x -1 / y -1 are drawn as out-of-bounds solid.
- An internal error is reported once via AP.reportError and the level then uses AP.R.drawTilesFallback.

## AUDIO — as-built notes

Resume status: nothing from an earlier run survived (js/audio did not exist), so all three files were written from scratch in this run.

AS-BUILT AP.Audio
- init() creates no context and hooks events. unlock() creates the AudioContext (latencyHint 'interactive', with a webkitAudioContext fallback), resumes it, plays a 1-sample iOS unlock blip and is idempotent.
- ready is true only while the context state is 'running'. Input therefore calls unlock() again on the next gesture after an autoplay block or Safari 'interrupted'.
- Before the context runs, sfx() is dropped. The latest music(key|null, {fade}) request and the loop volumes are remembered and applied when it starts running. setIntensity and setVolumes store their values.
- At first run, volumes are read from AP.Save.data.settings (master, music, sfx) and mapped as v² times a trim. They are re-read on settings:changed for keys master/music/sfx/'*'. CORE's main.js also calls setVolumes; both paths agree.
- Graph: sfx bus and music bus (music → pause lowpass → duck gain) → master gain → DynamicsCompressor (-14 dB, ratio 4) → destination.
- Shared sends: a reverb with a synthesized 2.6 s stereo impulse (high-passed at 230 Hz) and a tempo-synced ping-pong delay whose echoes return to the music bus. Noise buffers are 1.5 s white and 2.5 s pink. All of this is generated once at unlock in a few milliseconds.
- Voice pools: 24 SFX voices steal the oldest. Each SFX recipe can also set a per-name cooldown and instance cap (step 45 ms/2, type 28 ms/2, shard 20 ms/4, …).
- The 12 music voices steal the oldest voice that is already in its decay tail (past 60% of its life), and fall back to the oldest. This cut audible early steals by about 3x. All drum hits of one layer on one step share a single voice.
- duck(amount, dur) merges overlapping ducks (deepest and longest win). Audio also ducks by itself on player:death (0.5, 0.75 s) and form:gain (0.7, 2.2 s), and through the death, vertex, complete, explode, bossHit, bossPhase, bossRoar and bossDeath recipes. CORE's own duck calls merge with these.
- setLoop(wind|hum|void, 0..1) builds persistent generators lazily and glides their gain. Volume 0 fades out, and the nodes are torn down after 3 s. Calling it every frame is cheap: it only acts when the change exceeds 0.004.
- Loop volumes reset to 0 on level:start, on level:quit and when the scene stack no longer contains 'level'.
- While a scene is pushed over 'level' (pause, settings), or AP.level.paused is set (LevelScene's inline pause), loops fade out and music is muffled to 900 Hz. Both are restored on return.
- setIntensity: the effective value is max(explicit, auto). Auto comes from boss events: boss:start gives 0.45, then each boss:phase raises it toward 1.0, using bossInfo.phase/phases and treating the phase at boss:start as the base.
- Explicit intensity resets to 0 on level:start and when leaving the level. LevelScene re-sends L.intensity on its next step because sentIntensity starts at -1.
- Layers by intensity:
  - Base (pad, bass, arp, lead, percussion) is always on, so normal levels at 0.35 hear the clean full arrangement.
  - extra (counter-line and extra percussion) fades in over 0.4–0.6.
  - drive fades in over 0.62–0.8.
  - peak (fills and crashes) fades in over 0.85–0.97.
  - The tone filter opens with intensity. Layer changes glide over about 0.7 s, and a removed layer keeps composing for 2.2 s so it fades rather than cuts.
- tick() runs the composer: lookahead 0.12 s from AP.Beat.beat and realBpm(). The beat-to-audio-time mapping is smoothed. It resyncs when the beat jumps back (Beat.reset continues the composition at the next bar), on a tempo or assist change, or on a stall over 80 ms.
- Nothing is ever scheduled before currentTime: a step up to 30 ms late plays immediately, anything later is skipped. Output latency is compensated by clamp(outputLatency − 16 ms, 0, 60 ms).
- suspend()/resume() pause and resume the context, and resume resyncs the composer. Every entry point is wrapped in try/catch; real bugs are reported once per label through AP.reportError.

SFX (sfx.js)
- All 47 names are parametric recipes built from the synth kit: oscillator tones with sweeps, two-operator FM, filtered noise, ADSR envelopes and waveshaping. Every recipe honours {vol, pitch, pan}.
- Key-aware recipes (shard, chime, gem, checkpoint, secret, vertex, complete, respawn, bossPhase, bossDeath) use AP.Audio.tonic(), so pickups always sit in the music's key.
- Jump/jump2/walljump: the form interval comes from AP.level.player.form (triangle → circle spans 0/+2/+4/+7/+12 semitones), and the waveform follows the form. CORE's player.js already passes its own form pitch (1+(min(sides,8)-3)*0.06, +0.1 for the circle). That exact value is recognised and not applied twice; any other pitch multiplies.
- Shard: common.js drives its own 0.6 s chain by passing pitch = 2^(major-pentatonic step/12). The chain step is recovered from that pitch and re-mapped onto the key's pentatonic (minor pentatonic in minor modes). The internal 0.6 s climb only runs when no caller drives the pitch.
- Step and land are tinted per world style: glassier in w2, softer in w3, earthy in w4.

MUSIC (music.js)
- Each key is a seeded generator, and the piece is a pure function of (key seed, song bar). It is built from 8-bar sections in an A A' B A'' cycle; the A theme mutates each cycle.
- Chord progressions are modal and weighted toward each mode's characteristic chord, with cadences at section ends.
- The motif is developed by transposition, inversion, retrograde, rotation, ornament, fragmentation and, for w4/boss4, augmentation and diminution: motif, then augmented, then diminished. boss4 layers the motif at three time scales (bass augmented, lead, extra diminished).
- Rhythms are Euclidean (AP.Algo.euclid, with a private Bjorklund fallback identical on all 11,968 patterns tested) and rotate between sections. Breakdown sections give long-form contrast.
- The pad is persistent: 4 voices × 2 detuned oscillators (FM, saw, triangle, formant choir or drone), voice-led and gliding between chords. The title pad glides slowly, giving the morphing chord. These 8–12 persistent oscillators per song are outside the 12-voice note pool.
- Per-key character follows DESIGN §8: W1 E(5,12) hats with root-third-fifth walking bass, W2 E(5,16) shakers with sub pulse and long reverb, W3 3+2 grouping with kick on beats 1 and 4, flute and wind swells, W4 swung shakers with marimba and kalimba.
- w5/boss5 add 3:4:5 pulses per bar, panned left/centre/right.
- w5 moves from Phrygian dominant toward Lydian in later sections and later W5 levels (by AP.level.index).
- boss5 brightens with each phase (Locrian → Phrygian → Aeolian → Phrygian dominant) and resolves to Lydian on boss:defeat. This also applies to the song that is fading out, because LevelScene calls AP.music(null, {fade: 2.5}) before emitting boss:defeat.
- endless takes its root and mode from AP.level.style or endless:segment {style}.
- Crossfade: music(key) fades the old song out while it keeps composing on its own last grid, and fades the new one in. Same key is a no-op.

HEADLESS NOTE: AP.boot({headless:true}) attaches no DOM listeners, so boot-test must call AP.Audio.unlock() directly. A synthetic keydown will not unlock in headless mode.

### AUDIO — known gaps

1. tools/boot-test.js does not exist yet (TOOLS had not delivered it when I finished), so `node tools/boot-test.js --audio` could not be run. `node tools/check-all.js --owner AUDIO` therefore fails only at its owner-test step, with MODULE_NOT_FOUND for that file; every other step passes. My own stub-AudioContext test covers the stated boot-test --audio criteria and passes.
2. No browser listening test (not permitted in this run). Mix balance, timbres and loudness trims were set by gain-staging estimates, not by ear. The INTEGRATOR's browser smoke check should listen for music versus SFX balance and overall level; Chrome's compressor adds about +6 dB of automatic makeup gain.
3. The 12-voice music cap still forces some voice steals in the densest boss/w5/endless passages at full intensity. In the stress test about 1–2 per second hit a voice before its quiet tail; normal-level keys have almost none.
4. The jump and shard pitch fixes depend on CORE's current conventions: player.js's form pitch formula and common.js's SHARD_STEPS passed as pitch. If CORE changes those formulas, jumps get the caller pitch multiplied on top of the form interval, and shards fall back to raw pitch multiplication. Nothing breaks, but the result is less musical.
5. LevelScene's inline-pause detection reads the undocumented field AP.level.paused (used only when no 'pause' scene exists). The overlay-scene path uses the documented scene:change event and AP.Scenes.stack.
